# Chelsy AI 0.9 — Host, Windows Client, Android Client, Cloud Sync

**Это исходный проект и скрипты сборки, а не готовые EXE/APK.** Для Windows-сборки требуется ПК Windows 10/11 x64; для APK — Flutter + Android SDK. Сборка и проверка на двух реальных устройствах ещё не проводилась.

## Что внутри

| Каталог | Что делает |
|---|---|
| `ChelsyAI_0.9_Windows/` | Полный Desktop, Host API, отдельный Windows-клиент и скрипты сборки `.exe` |
| `Android_Client/` | Flutter-проект мобильного клиента, скрипт сборки `.apk` |
| `ChelsyGroup_Web/` | Копия сайта с новой страницей `history.html` (только просмотр облачной истории) |

## 1. Безопасность и сохранность данных

* **Не удалять** `%LOCALAPPDATA%\ChelsyAI\data` — существующая SQLite-память и история живут там.
* Перед обновлением сделай копию `%LOCALAPPDATA%\ChelsyAI` на внешний диск.
* Не публикуй порт Ollama `11434` или Chelsy Host `8787` в интернет.
* Tailscale **Serve**, не Funnel. Другу нужен доступ к твоему tailnet (в соответствии с его настройками ACL).
* Единственный источник личности: существующий Supabase Auth сайта. Host проверяет bearer-токен у Supabase на каждый запрос. Basic-авторизация отключена по умолчанию.
* Публичный Supabase `publishable_key` в приложении — это нормально. Не помещай `sb_secret`, `service_role` или пароль к базе ни в APK, ни в EXE.
* Если сайт имеет оплачиваемые тарифы в будущем, **проверяй оплаты сервером**, а не по выбранному в анкете тарифу. В 0.9 проверки платежей и квот **нет**.

## 2. Supabase — нужно сделать один раз

1. Открой **Supabase Dashboard → SQL Editor** проекта Chelsy Group.
2. Сделай резервную копию. Сначала **на тестовом проекте** выполни `ChelsyAI_0.9_Windows/supabase/001_chelsy_ai_data.sql`.
3. Примени `supabase/002_cloud_sync_indexes.sql`.
4. Проверь, что на `public.chelsy_ai_messages` и `public.chelsy_ai_memories` включён RLS, а политики дают доступ только `auth.uid() = user_id`.
5. На рабочем проекте примени миграции только после проверки. Эти SQL не меняют `auth.users`, `profiles`, подписки сайта или пароли.

**Не запускай `001` повторно, не проверив её содержимое:** политики создаются через `create policy` без `if not exists`.

## 3. Установка Host на твоём Windows-ноутбуке

Установи Python 3.11, Inno Setup 6/7, Ollama и скачай модель:

```powershell
ollama pull llama3.2:1b
```

В папке `ChelsyAI_0.9_Windows` дважды нажми `BUILD_INSTALLER.bat`. В конце, если всё успешно, получишь:

* `installer\ChelsyAI_Setup_0.9.exe` — **полное приложение с Host**.
* `installer\ChelsyAI_Client_Setup_0.9.exe` — **отдельный лёгкий клиент**.

Установи полный пакет на свой ноутбук. Запусти **Chelsy AI Supabase Setup**, проверь публичные URL/key уже из проекта Chelsy Group, сохрани. Запусти **Chelsy AI Host** из меню «Пуск». Он запускается только на `127.0.0.1:8787`.

Открой терминал Windows и настрой Tailscale Serve:

```powershell
tailscale serve 8787
tailscale serve status
```

Запомни HTTPS-адрес вида `https://ИМЯ-НОУТБУКА.ИМЯ-TAILNET.ts.net`. Адрес, имя и разрешения выдаёт Tailscale — **не придумывай свой адрес**. Убедись, что служба активна. Функция Serve может требовать включить HTTPS certificates в tailnet.

## 4. Установка Windows-клиента другу

Отправь только **готовый** `ChelsyAI_Client_Setup_0.9.exe` после сборки. Другу нужны:

* Windows 10/11, интернет, доступ в Tailscale к твоему ноутбуку;
* установщик клиента; Ollama и модель не требуются;
* собственный зарегистрированный аккаунт Chelsy Group (Supabase Auth).

После установки: **Chelsy AI Supabase Setup → Chelsy AI Client**, вставить HTTPS-адрес сервера, войти под email и паролем сайта, нажать «Войти и открыть историю». Кнопка «☁ Синхронизация» отправляет накопленные данные и загружает облачную историю.

## 5. Android APK

На ПК с Flutter SDK, Android SDK, Java (проверь `flutter doctor -v`) открой `Android_Client` и запусти `BUILD_ANDROID_APK.bat`. На первом запуске он создаёт Android-обвязку через `flutter create`, добавляет разрешение `INTERNET`, скачивает зависимости и выполняет сборку.

Ожидаемый файл **после успешной сборки на Windows**:

```text
Android_Client\build\app\outputs\flutter-apk\app-release.apk
```

Установи APK на Android, установи Tailscale и подключись к доступному tailnet, введи HTTPS-адрес сервера и войди через Supabase. Android-клиент использует Supabase для сессии; если ноутбук выключен, можно открыть облачную историю, но не генерировать новые ответы. При первом запуске Tailscale должен иметь доступ к серверу.

**APK из этого проекта — тестовая сборка:** для публичного распространения потребуется production-подпись приложения своим keystore, проверка Android SDK/версий и политика обновлений. Мы не создали здесь подписанный выпуск для Google Play.

## 6. История сайта

`ChelsyGroup_Web/history.html` — новая защищённая авторизацией страница чтения облачных сообщений через Supabase RLS. `account.html` теперь содержит ссылку на неё. Сайт не может самостоятельно обратиться к твоему приватному Tailscale-хосту из браузера посетителя — это намеренное ограничение безопасности. Новый сайт **не опубликован** на Netlify автоматически. Перед публикацией тестируй на staging.

## 7. Как работает синхронизация

* Host/Windows Desktop перед получением ответа подгружают облачные сообщения в локальную SQLite и отправляют новые после ответа.
* Windows/Android клиенты видят историю Host; Android и сайт могут просматривать **облачную** историю, пока ноутбук выключен.
* Для сообщений используется `legacy_id=host:<SQLite ID>` и маркеры импортированных записей, чтобы не создавать дубликаты при повторах.
* Память синхронизируется по `user_id + memory_key`; локальные офлайн-редактирования помечаются для последующей загрузки.
* При недоступности облака локальная история остаётся. После восстановления связи открой историю или нажми «Синхронизация».
* История ограничена 5000 записями для начальной облачной загрузки, интерфейс показывает последние 30 диалоговых сообщений Host; облачные страницы сайта/Android показывают до 500 записей. Это ограничения beta.
* Если данные уже находились под локальными `owner/tester`, нужен **отдельный однократный перенос** с помощью `ChelsyMigrate`/`ChelsyUpload`, как в 0.8. Самопроизвольно смешивать эти учётные записи с аккаунтами сайта нельзя.
* В 0.9 нет серверной синхронизации всего сайта в реальном времени, централизованных платежей/квот, фонового клиента при выключенном устройстве, пуш-уведомлений и автоматической установки обновлений.

В каталоге `ChelsyAI_0.9_Windows`:

## 9. Как автоматически получить готовые EXE/APK через GitHub Actions

В едином ZIP есть `.github/workflows/build-clients.yml`. Он может собрать **реальные установщики в облачном Windows runner и APK в Android runner** — без Python/Flutter на твоём ноутбуке. Но мы ещё **не запускали этот workflow на GitHub**, и возможны ошибки зависимостей/сборки.

1. Создай **приватный** репозиторий GitHub для исходников Chelsy AI.
2. Загрузи **содержимое папки `ChelsyAI_0.9_RELEASE` в корень репозитория**, включая скрытый каталог `.github/`.
3. GitHub → **Actions** → **Build Chelsy AI 0.9 installers** → **Run workflow**.
4. После успешного выполнения открой запуск и скачай два набора **Artifacts**: `ChelsyAI-0.9-Windows-EXE` и `ChelsyAI-0.9-Android-APK`.
5. Перед отправкой друзьям проверь вход и память на своих тестовых аккаунтах. Это автоматическая сборка, а не автоматическое тестирование реальных устройств.

**Важная деталь:** GitHub Actions artifacts — ZIP-пакеты с бинарниками внутри, а не публичный прямой URL установщика. Для постоянной раздачи используйте GitHub Releases или свой контролируемый сервер обновлений после тестирования. Пароль Supabase и service_role не добавляй в репозиторий.
