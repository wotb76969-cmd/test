# Chelsy AI 0.9.3 — модель безопасности

## Сеть
- **Host** слушает только `127.0.0.1:8787`; доступ извне — через Tailscale Serve (HTTPS внутри частной сети). Ollama (`127.0.0.1:11434`) клиентам недоступна; адрес Ollama принудительно ограничен loopback (`ollama_client.py`).
- Desktop (Gradio) — только `127.0.0.1`, `share=False`, API Gradio закрыт (`api_open=False`), шрифты не грузятся с внешних CDN. (Сам Gradio подключает скрипт `iframeResizer` с cdnjs — данные пользователя туда не передаются.)
- Заголовки Host: `no-store`, `nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`. Ограничения: размер тела (12 КБ / 70 КБ для чата с файлами), 12 запросов к модели в минуту на пользователя, проверка UUID/моделей/вложений.

## Аккаунты и данные
- Единый Supabase Auth. В клиентах только URL проекта и **publishable**-ключ; ключи `sb_secret_`/`service_role` отклоняются кодом, сборщиками и CI-проверкой.
- Host проверяет access-токен через Supabase (`/auth/v1/user`), кэширует результат по SHA-256 токена ≤ 90 с и не дольше `exp`; просроченные JWT отклоняются локально.
- Изоляция: все запросы SQLite фильтруются по ключу пользователя (`sb:<uuid>`); диалоги, исследования, личная база знаний, настройки — только владельцу (проверено тестами `test_host093`, `test_knowledge093`). Облако: RLS на всех таблицах + триггер, запрещающий привязку сообщения к чужому диалогу (проверено на PostgreSQL 16).
- Пароли никогда не сохраняются. Windows Client хранит только refresh-токен, зашифрованный **DPAPI** (только этот пользователь Windows на этом ПК). Android хранит сессию в **flutter_secure_storage** (Android Keystore).
- Удаление диалогов «мягкое»: данные остаются в SQLite и резервных копиях до ручной очистки.

## Исследование интернета
- Только http/https на портах 80/443, без логинов в URL. Все IP-адреса хоста должны быть публичными (запрещены localhost, частные сети, link-local, CGNAT/Tailscale `100.64/10`, multicast, metadata `169.254.169.254`, IPv4-mapped IPv6, `.local/.internal/.ts.net`, однословные имена).
- Соединение «прибивается» к проверенному IP (нет окна DNS-rebinding), TLS проверяет сертификат исходного имени; каждый редирект проверяется заново (≤ 4).
- robots.txt по RFC 9309, crawl-delay ≥ 3 с на сайт, ≤ 20 запросов в минуту, ≤ 2 МБ на страницу, только HTML/текст. Скачанное никогда не исполняется.
- Инструкции для ИИ внутри страниц вырезаются и снижают оценку доверия; тексты источников в промпте помечены как недоверенные данные. E-mail и телефоны третьих лиц маскируются перед сохранением.
- Периодические задачи — только по разрешённым владельцем доменам; в общую базу материалы добавляет только владелец.

## Windows
- Установка в профиль пользователя (`PrivilegesRequired=lowest`), без служб и открытых портов наружу.
- Ресурс версии во всех EXE; подпись Authenticode (SHA-256 + RFC 3161 timestamp) при наличии сертификата (`CHELSY_SIGN_PFX`). **Без сертификата установщики не подписаны** — SmartScreen покажет предупреждение; для распространения нужен собственный сертификат подписи кода.
- `SHA256SUMS.txt` для проверки целостности.

## Android
- Единственное разрешение — `INTERNET`. `usesCleartextTraffic=false`, network security config: только HTTPS и только системные CA (пользовательские сертификаты не доверяются).
- `allowBackup=false`, `dataExtractionRules` исключают всё из облачных копий и переноса.
- Release-сборка: обязательная подпись release-ключом (Gradle отказывается собирать без него), R8 minify + shrink, `--obfuscate`, не debuggable (проверяется в CI через `aapt`), подпись проверяется `apksigner`.
- Открываются только `https`-ссылки из ответов.
- Для обновлений поверх установленной версии нужен **один и тот же** ключ подписи: сохрани keystore и добавь его в секреты CI (`ANDROID_KEYSTORE_BASE64` и др.).

## Не делается (сознательно)
- Нет автоматического изменения весов модели. Дообучение — ручной процесс владельца с порогом качества и откатом.
- Нет публичного доступа к Host из интернета.
