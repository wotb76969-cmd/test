# Chelsy AI 0.9.2 → 0.9.3: аудит и план изменений

Исходник: `ChelsyAI_0.9.2_RUSSIAN_ANSWER_FIX_SOURCE.zip` (импортирован без изменений первым коммитом `Import Chelsy AI 0.9.2 source`).

## 1. Архитектура 0.9.2 (что было)

| Компонент | Файл | Состояние |
|---|---|---|
| Ядро: SQLite, память, обходчик, ответ | `core.py` | один монолитный `answer()`, таблицы создавались при каждом открытии БД |
| Desktop UI | `app.py` (Gradio 6.5.1) | вкладки «Чат / Исследования / Память / Подключения / Настройки», без диалогов |
| Качество ответов | `response_quality.py` | только проверка смешения русского с английским |
| Онлайн | `live_tools.py` | погода (Open-Meteo), Brave Search, шаблонные приветствия |
| Host API | `host_server.py` | `/api/status, /history, /chat, /memory, /sync`, один запрос к модели за раз |
| Windows Client | `client.py` (Tk) | одна лента сообщений, без стриминга |
| Авторизация | `supabase_auth.py`, `desktop_auth.py` | Supabase Auth (publishable key), проверка токена на каждый запрос |
| Облако | `cloud_sync.py`, `supabase/001–002` | сообщения и память, RLS |
| Android | `Android_Client/lib/main.dart` | один экран, без android/-проекта (генерировался в CI) |

## 2. Найденные проблемы

**Данные и синхронизация**
1. Нет версионированных миграций и резервных копий SQLite — схема менялась «на лету» (`CREATE TABLE IF NOT EXISTS` при каждом подключении).
2. Нет диалогов: все сообщения пользователя — одна лента; невозможно «Новый чат», избранное, поиск, редактирование.
3. `legacy_id = 'host:<локальный id>'` — у двух хостов одного пользователя id совпадают, и `unique(user_id, legacy_id)` молча отбрасывал сообщения второго хоста (**потеря данных**).
4. Каждая синхронизация заново отправляла до 5000 сообщений и все воспоминания (лишний трафик).
5. Очистка истории физически удаляла облачные сообщения.

**Ответы**
6. Шаблонные приветствия вместо живого ответа модели; жёсткий список из двух моделей (`llama3.2:1b`, `qwen3:4b`).
7. Нет потоковой генерации, остановки, повтора, контекстного окна (брались последние 8 сообщений без учёта размера).
8. Нет обнаружения бессвязных ответов, повторов, иероглифов, ложных заявлений «я поискала в интернете».
9. Поиск по знаниям — перебор всех страниц в Python, без дедупликации, дат, версий и эмбеддингов.

**Безопасность**
10. Обходчик: проверка DNS и подключение — разные шаги (окно DNS-rebinding); robots.txt со статусом 404 трактовался как запрет (большинство сайтов не исследовалось).
11. Текст веб-страниц попадал в промпт без нейтрализации инструкций (prompt injection), личные данные третьих лиц сохранялись.
12. Android: сессия Supabase в SharedPreferences, нет network security config, разрешены резервные копии, release-APK подписывался debug-ключом CI.
13. Нет кэша проверки токенов — каждый запрос к Host ходил в Supabase.

**Сборка и тесты**
14. Импорт `client.py` требовал tkinter → один тест падал в средах без Tk; тестов на движок, знания, хост v2, Android не было.

## 3. План (выполнен)

1. `migrations.py` — версии v1 (схема 0.9.2), v2 (диалоги, стабильные id сообщений, оценки, настройки), v3 (база знаний); бэкап перед каждой миграцией, откат.
2. `intelligence.py` — Chelsy Intelligence Engine: персона, адаптивная длина, контекстное окно, маршрутизация, RAG, стриминг с остановкой, проверки и одна контролируемая перегенерация.
3. `knowledge/` — SearchManager, SourceFetcher, ContentExtractor, KnowledgeIndexer, KnowledgeRetriever, SourceVerifier, ResearchScheduler, KnowledgeDatabase.
4. `training/`, `model_eval.py` — отдельный контролируемый конвейер дообучения и оценка моделей.
5. Host API v2 (совместим с 0.9.2), новый Desktop UI, новый Windows Client, Android-клиент.
6. Supabase 003 (диалоги, мягкое удаление) + откат + тест RLS на реальном PostgreSQL.
7. CI: тесты → установщики Windows → подписанный APK с проверкой манифеста.
