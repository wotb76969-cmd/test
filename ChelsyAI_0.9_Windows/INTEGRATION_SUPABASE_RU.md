# Chelsy AI 0.8 — единый Supabase Auth (закрытая бета)

## Что реализовано

* `Chelsy AI` (локальный Desktop, Gradio) использует учётную запись существующего Supabase Auth, если настроен проект. В режиме без конфигурации остаются прежние локальные `owner`/`tester`.
* `Chelsy AI Client` выполняет вход по email+паролю непосредственно в Supabase Auth, получает access token только в оперативной памяти и передаёт хосту Bearer token. Пароль Supabase **не** передаётся на Chelsy Host.
* `Chelsy AI Host` проверяет каждый Bearer-токен через Supabase `/auth/v1/user`, использует стабильный UUID `auth.users.id` для изоляции локальных сообщений и памяти. В Supabase-режиме старый Basic-вход на Host запрещён.
* Старые файлы `%LOCALAPPDATA%\ChelsyAI\data\chelsy.db` и `users.json` не удаляются. `ChelsyMigrate.exe` переносит записи одного локального аккаунта в пространство UUID только после проверки локального пароля и пароля существующего Supabase-аккаунта, создаёт SQLite backup. Исходные записи не удаляются.
* `ChelsyConfig.exe` настраивает URL проекта, **публичный** publishable / anon key и необязательный UUID администратора в `%LOCALAPPDATA%\ChelsyAI\supabase.json`.

## Что пока НЕ реализовано

* **Нет непрерывной облачной синхронизации сообщений и памяти.** Данные с ноутбука остаются в SQLite на ноутбуке. Два устройства, подключённые к одному Host с одним аккаунтом, видят его историю; на другом Host автоматически она не появится.
* SQL `supabase/001_chelsy_ai_data.sql` создаёт отдельные таблицы и RLS. Для разового переноса в облако есть `ChelsyUpload.exe` (сначала preview, потом --upload). Таблицы не создаются автоматически. Не запускайте SQL без проверки существующих таблиц и разрешений.
* Desktop/Client в этой версии поддерживают email+password. Если на сайте настроены Google/OAuth, magic links, MFA или OTP, потребуется дополнительный браузерный OAuth/PKCE-поток.
* Настройки подписок Start/Plus/Pro/Teams и оплата пока не подключены. Нельзя доверять заявленному клиентом тарифу.

## Как настроить

1. Сделайте резервную копию Supabase проекта и папки `%LOCALAPPDATA%\ChelsyAI\data`.
2. В Supabase Dashboard → Project Settings → API найдите **Project URL** и **publishable key** (`sb_publishable_...`) или legacy anon key. **Никогда не копируйте service_role или sb_secret.** URL и publishable key публичны по своей природе, но RLS должна быть настроена правильно.
3. После установки 0.8 запустите **Chelsy AI Supabase Setup** из меню Пуск. Введите URL и publishable key. UUID администратора нужен лишь для доступа к функциям исследования в Desktop и должен быть подтверждён в Supabase Auth. На обоих ПК требуется указать **один и тот же проект Supabase**.
4. Перезапустите Chelsy AI, Host и Client. Убедитесь, что сайт использует **тот же Supabase project ref**, не отдельный тестовый проект.
5. Войдите на Desktop через email+пароль от сайта. Для Client установите Tailscale и запустите Host на ноутбуке; `tailscale serve 8787` публикует приватный HTTPS-адрес для клиентского устройства внутри tailnet. Не используйте Funnel и не пробрасывайте Ollama или Host на публичный порт.
6. Перед миграцией сначала проверьте, что в новом аккаунте нет конфликтующих данных. Для локального копирования из owner:

   ```powershell
   & "$env:LOCALAPPDATA\Programs\ChelsyAI\Migration\ChelsyMigrate.exe" --old-user owner --email you@example.com
   ```

   Подставьте ваш email, вводите пароли только в собственное окно программы; они не отображаются и не записываются в файлы. Скрипт не удаляет исходную память и не переносит её в облачную базу.
7. Для облачной таблицы истории и памяти предварительно изучите `supabase/001_chelsy_ai_data.sql` и примените его только после теста в staging. Полную синхронизацию добавим после проверки схемы сайта.

## Важно для безопасности

* Только HTTPS для Supabase; Host только на 127.0.0.1 за Tailscale Serve.
* Не кладите `service_role`, `sb_secret_`, JWT signing secret или пароль БД в EXE, репозиторий или конфигурацию.
* `auth.uid()` должен проверяться RLS для каждой операции; таблицы без RLS нельзя выпускать в публичную бету.
* Для промышленной версии необходима проверка отзыва токенов, обновление сессии, ограничение частоты логинов и тестирование доступа между разными Supabase UID.
* Если пароль/токен уже утёк, отзовите токен/смените ключ; не включайте в логи или скриншоты.

## Дополнительно: разовый перенос сообщений и памяти в PostgreSQL Supabase

После применения и проверки `supabase/001_chelsy_ai_data.sql` можно выполнить **сначала без** `--upload`:

```powershell
& "$env:LOCALAPPDATA\Programs\ChelsyAI\CloudUpload\ChelsyUpload.exe" --old-user owner --email you@example.com
```

Затем добавьте `--upload` для действительного импорта. Импорт пропускает уже существующие строки по `(user_id, legacy_id)` и `(user_id, memory_key)` и не удаляет локальные записи. При сбое сети возможен частичный импорт; повторная попытка безопасна для тех же ключей. Это **одноразовый перенос**, а не фоновая синхронизация: последующие чаты пока продолжают храниться на Host в SQLite.
