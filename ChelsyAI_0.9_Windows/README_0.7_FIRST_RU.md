# Chelsy AI 0.7 — единая локальная бета

## Что внутри

- ChelsyAI.exe — локальный интерфейс с Ollama и SQLite
- ChelsyHost.exe — API-сервер для подключений по приватной сети
- ChelsyClient.exe — лёгкий клиент для второго Windows-ПК; Ollama ему не нужна
- Фоновое исследование **только из заранее добавленной очереди**, опционально, с ограничением числа страниц за цикл
- Документ `CHELSY_GROUP_ACCOUNT_INTEGRATION_RU.md` — схема будущей общей авторизации сайта и приложений

## Как собрать на Windows

1. Python 3.11 и Inno Setup 6/7 на Windows 10/11.
2. Распаковать ZIP в папку без кириллицы, например `E:\ChelsyBuild07`.
3. Запустить `BUILD_INSTALLER.bat`.
4. При успешной сборке получить `installer\ChelsyAI_Setup_0.7.exe`.
5. Если ISCC.exe не найден — открыть `ChelsyAI.iss` через Inno Setup и нажать F9 (предварительно должны существовать все три папки dist).

**Готовый EXE в архив не включён:** собирать и проверять его необходимо на Windows. Нет автоматической установки Ollama или Tailscale.

## На ноутбуке — хост

1. Установить и проверить Ollama: `ollama list`; убедиться, что модель `llama3.2:1b` загружена.
2. Запустить локальную Chelsy AI и создать аккаунты `owner` и `tester` с разными паролями.
3. Запустить «Chelsy AI Host» из меню Пуск. Сервер слушает ТОЛЬКО `127.0.0.1:8787`.
4. Установить Tailscale на ноутбук и устройство друга. Разрешить доступ только конкретному тестеру.
5. В PowerShell запустить `tailscale serve --bg 8787`; команда должна вывести приватный URL вида `https://...ts.net`.
6. Не использовать Tailscale Funnel; не открывать порт 8787 на роутере; не публиковать Ollama (11434) в сеть.

> В зависимости от версии Tailscale синтаксис `serve` может отличаться — ориентируйтесь на текущую справку `tailscale serve --help`. Хост должен быть включён для ответов.

## На ПК друга — клиент

1. Поставить **тот же установщик**, запустить «Chelsy AI Client» из меню Пуск.
2. Установить Tailscale и подключиться к разрешённой приватной сети.
3. Ввести HTTPS URL приватного Chelsy Host, логин `tester` и отдельный пароль.
4. «Подключиться и открыть историю», затем отправить сообщение.

Оба аккаунта имеют независимые истории и личную память в одной локальной БД хоста. Друг НЕ должен получать пароль `owner`. Basic-авторизация допустима только поверх доверенного Tailscale HTTPS в этой закрытой бете; для сайта/публичного запуска нужна токенная авторизация с проверкой подписей на сервере.

## Автоматический сбор знаний

- В локальном приложении аккаунтом owner добавить разрешённый публичный URL.
- По желанию включить фоновый обход в интерфейсе или запустить хост с `CHELSY_AUTO_CRAWL=1`.
- На сервере лимит — до 2 страниц за цикл, интервал по умолчанию 60 минут.
- Контент сохраняется в базе знаний, **не переобучает веса LLM**.
- `robots.txt` учитывается; из-за рисков обхода и безопасности не включайте массовый краулинг и не используйте произвольные URL от тестеров.

## Важные ограничения

Это закрытая бета, не коммерчески защищённый публичный сервис. Не используйте текущую локальную SQLite/JSON-пару для авторизации пользователей публичного сайта, не публикуйте приватный хост и не храните платежные реквизиты в этом приложении. Дополнительно потребуются резервные копии и защита от сбоев сети, проверка TLS, ограничение расходов и аудит безопасности. Платные тарифы сайта пока не подключены.
